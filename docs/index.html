Ruby gem · Simulated Annealing

Find good answers in messy search spaces.

Annealing is a Ruby library for simulated annealing. You describe a state, how to score it, and how to change it. The gem explores the search space by balancing improvement with occasional risk.

01 / Why

Why this project exists

Many real problems have too many possible combinations to evaluate exhaustively. Simulated annealing gives you a practical search strategy: try nearby states, prefer improvements, and sometimes accept worse moves to escape local dead ends.

The problem

Routing, scheduling, packing, layout, and assignment problems often involve competing constraints. The perfect answer may be expensive or impossible to compute directly.

The approach

Annealing explores neighboring states. It always prefers lower energy, but at higher temperatures it can accept a worse state with a probability based on temperature.

The tradeoff

You get a flexible, domain-agnostic search. The quality of the result depends on how you model energy, state changes, cooling, and termination.

02 / Inspiration

The original spark

This repository was inspired by SciShow’s The Most Metal Algorithm in Computer Science, which explains simulated annealing through the metallurgy metaphor.

Video by SciShow. Embedded from youtube-nocookie.com.

From cooling metal to code

In physical annealing, metal is heated and cooled slowly so atoms can settle into a low-energy arrangement. The algorithm uses the same idea:

  • State — a candidate solution.
  • Energy — the cost or badness of that solution.
  • Temperature — how willing the search is to explore.
  • Cooling — gradually reducing that exploration over time.

Early randomness helps avoid getting stuck. Later stability helps the search converge on a strong answer.

03 / Process

How it works

The simulator runs a simple loop. You provide the domain logic; Annealing handles temperature, acceptance, and iteration.

1

Start

Begin with an initial state and temperature.

2

Score

Compute energy with energy_calculator. Lower is better.

3

Change

Generate a neighboring state with state_change.

4

Decide

Accept better moves; sometimes accept worse moves while hot.

5

Cool

Reduce temperature until the termination condition is met.

Important: at temperature zero, Annealing accepts only strictly lower-energy states. Equal or higher energy is not accepted.

05 / Quick start

Quick start

A small traveling-salesperson example. It uses a custom temperature and cooling rate so the first run finishes quickly.

Ruby

require "annealing"

Location = Struct.new(:x, :y) do
  def distance(other)
    dx = (x - other.x).abs
    dy = (y - other.y).abs
    Math.sqrt(dx**2 + dy**2)
  end
end

locations = [
  Location.new(60, 200),
  Location.new(180, 200),
  Location.new(40, 120),
  Location.new(100, 120),
  Location.new(20, 40)
].shuffle

energy_calculator = lambda do |step|
  step.state.each_cons(2).sum { |a, b| a.distance(b) }
end

state_change = lambda do |step|
  swapped = step.state.dup
  i, j = Array.new(2) { rand(swapped.size) }
  swapped[i], swapped[j] = swapped[j], swapped[i]
  swapped
end

route = Annealing.simulate(
  locations,
  energy_calculator: energy_calculator,
  state_change: state_change,
  temperature: 5_000,
  cooling_rate: 0.5
)

p route.map { |loc| [loc.x, loc.y] }
Default scale: with the default temperature: 10_000 and cooling_rate: 0.0003, the linear cooler considers about 33 million proposed states. Use smaller values while experimenting.
06 / Configuration

Configuration

Configure globally with Annealing.configure, per instance with Annealing::Simulator.new, or just in time with simulate/run. Precedence: global < simulator instance < just in time.

OptionDefaultPurpose
cool_downCoolers.linearReturns the next temperature from an Annealing::Step.
cooling_rate0.0003Used by the default linear cooler; exposed as step.cooling_rate.
energy_calculatorRequiredScores a state. Lower is better. Use step.state, not step.energy.
state_changeRequiredReturns the next candidate state from step.state.
temperature10_000.0Initial temperature. Higher values allow more exploration.
termination_conditionTerminators.temp_is_zero?Stops the simulation when it returns true.
return_bestfalseReturn the lowest-energy state seen, not just the final state.

Step object

Custom functions receive one read-only Annealing::Step:

  • state — current state.
  • energy — current energy.
  • temperature — current temperature.
  • cooling_rate — configured cooling rate.
  • steps — completed steps.

Built-ins

Coolers

  • Coolers.linear
  • Coolers.exponential
  • Coolers.geometric(ratio)

Terminators

  • Terminators.temp_is_zero?
  • Terminators.energy_or_temp_is_zero?
07 / Resources

Learn more

Use the architecture diagram for implementation details, and the README/changelog for API and release history.

Good fit

Use annealing when you can score candidates and generate nearby alternatives, but checking every possibility is impractical.

Tuning

Start small. Raise temperature or lower cooling rate for more exploration. Add a termination condition or return_best when runs get long or noisy.

Pitfalls

Do not call step.energy inside energy_calculator. Keep state changes local. Remember Annealing.simulate returns the state.
